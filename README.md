Архитектурный прототип классической игры «три в ряд» на Unity. Проект создан для демонстрации зрелого подхода к организации кодовой базы: строгий DI, управление состояниями, асинхронная загрузка ресурсов и надёжная система сохранений.

## 🚀 О проекте
Это не просто рабочая механика «три в ряд», а **референсная реализация** игрового цикла с чистой архитектурой. Основная цель — показать, как можно организовать проект так, чтобы его было легко расширять, тестировать и оптимизировать под разные платформы (Mobile / PC).

**Ключевые возможности:**
*   Полноценный игровой цикл: от главного меню до экрана победы/поражения.
*   Механика Drag-and-drop для обмена тайлов.
*   Пул объектов (Object Pooling) для FX и тайлов (снижение нагрузки на GC).
*   Асинхронная загрузка уровней и ассетов без фризов.
*   Система сохранения прогресса.

## 📂 Структура проекта и точка входа

Проект организован по принципу **слоёной архитектуры** с чёткими зонами ответственности[reference:1].

*   `Assets/Scripts/Boot/BootEntryPoint.cs` — **Главная точка входа**. Здесь инициализируется DI-контейнер и запускается последовательность загрузки игры.
*   `Assets/Scripts/DI/` — Настройка скоупов VContainer (`RootScope`, `MenuScope`, `GameScope`). Разделение скоупов позволяет жить глобальным сервисам (например, `SaveService`) и пересоздавать игровые зависимости при смене сцены.
*   `Assets/Scripts/GameStateMachine/` — Реализация паттерна **State Machine**. Управляет переходами между состояниями: `Bootstrap`, `Menu`, `Gameplay`, `EndGame`.
*   `Assets/Scripts/Game/` — Игровая логика (матчинг, доска, тайлы).
*   `Assets/Scripts/ResourcesLoading/` — Обёртка над Addressables для загрузки ассетов по требованию.
*   `Assets/Scripts/Save/` — Сервис сохранения/загрузки прогресса.
*   `buld/` — Готовая сборка проекта (Windows) для быстрого ознакомления.

## 🏗 Ключевые архитектурные решения

### 1. Управление зависимостями (VContainer)
Вместо синглтонов и `FindObjectOfType` используется DI-контейнер. Это позволяет легко подменять сервисы на моки при тестировании и делает код предсказуемым. Регистрация сервисов происходит в `LifetimeScope` (например, `RootScope.cs`), а внедрение — через конструкторы.

### 2. Асинхронность (UniTask)
Все длительные операции (загрузка сцен, анимации, ожидание ввода) переведены на `UniTask`. Это избавляет от аллокаций памяти, свойственных стандартным `Task` и корутинам, и позволяет использовать конструкцию `async/await` для написания последовательного и читаемого кода.
